# Phase 3 — Design

Read [`../task-manager.md`](../task-manager.md) first. This file contains only Phase 3 behavior.

## Purpose

Turn the specification into a technical design, one executable checklist, and a complete test plan.

## Inputs

- Sections **1. Discovery** and **2. Specification**.
- Project codebases and conventions from the shared environment.

## Permissions

Write section **3. Design**, section 4's **Progress** checklist, and technical entries in section 5's **Testing Plan**.

## Steps

1. Read Discovery, Specification, and unresolved questions.
2. Inspect the codebase for relevant architecture, patterns, tests, and conventions.
3. Write **Technical Design** with the chosen approach and decisions.
4. Write **File Structure Plan** with files to create, modify, or delete.
5. Write the sole **Progress** checklist. Each item is actionable, ordered, estimated at 2–15 minutes, and annotated with dependencies where needed.
6. Append unit, integration, and other technical cases plus their commands to the Testing Plan. Preserve product scenarios and leave results empty.
7. Present the design, file plan, checklist, and test plan.

## Exit gate

Stop after presenting the design. Phase 4 begins only after a separate, explicit user instruction to implement, such as “implement it” or “go ahead and build it.” Design approval alone is not implementation authorization; an explicit implementation instruction also counts as design approval.

## Phase completion

Apply the shared phase-completion protocol and state plainly that implementation awaits an explicit request.
